# Prompt maestro — Portfolio de Ingeniero Informático con identidad visual tecnológica roja

Quiero que construyas una web completa de portfolio profesional para un ingeniero informático/desarrollador.

## 1. Objetivo general

La web debe estar diseñada específicamente para presentar un perfil profesional de desarrollador, demostrar capacidades técnicas y mostrar proyectos de desarrollo.

No quiero una landing page genérica de SaaS ni una interfaz que parezca generada automáticamente por IA.

La web debe sentirse como una identidad visual creada específicamente para un ingeniero informático con criterio técnico, creativo y visual.

Un recruiter debería poder entender rápidamente:

* quién soy
* qué tipo de desarrollador soy
* qué tecnologías conozco
* qué proyectos he desarrollado
* qué problemas soy capaz de resolver
* cuál es mi nivel técnico
* dónde puede encontrar más información sobre mí

La web debe funcionar como una extensión visual de un CV y perfil de LinkedIn.

---

# 2. IMPORTANTE — Datos de demostración

Para esta primera implementación **SÍ debes utilizar datos inventados/ficticios** para poder visualizar cómo quedaría el portfolio completo.

Los datos ficticios deben utilizarse únicamente como contenido de demostración.

Puedes inventar:

* nombre
* descripción profesional
* experiencia
* formación
* tecnologías
* proyectos
* empresas
* fechas
* estadísticas
* enlaces ficticios
* información de contacto ficticia

Sin embargo, debes dejar claramente estructurada la información para que posteriormente pueda sustituirse fácilmente por los datos reales.

Utiliza datos de ejemplo creíbles y profesionales.

Por ejemplo, puedes utilizar un perfil ficticio como:

* Nombre: Alex Navarro
* Profesión: Ingeniero Informático / Full Stack Developer
* Especialidad: aplicaciones web, sistemas distribuidos y arquitectura de software
* Tecnologías: TypeScript, React, Node.js, PostgreSQL, Docker, Python, etc.

Los proyectos ficticios deben parecer proyectos reales y técnicamente creíbles.

No presentes los datos inventados como si fueran información real del usuario. Son únicamente contenido DEMO.

Cuando sea apropiado, utiliza comentarios en el código indicando qué información debe reemplazarse posteriormente.

# 3. Qué quiero construir

## Tipo de web

Portfolio personal de ingeniero informático / desarrollador.

## Objetivo principal

La web debe permitirme presentarme profesionalmente como ingeniero informático y mostrar principalmente mis proyectos de desarrollo.

## Público objetivo

Principalmente:

* recruiters
* hiring managers
* empresas tecnológicas
* otros desarrolladores o profesionales del sector

Muchas de estas personas probablemente dedicarán poco tiempo a revisar la web, por lo que la información importante debe ser fácil de encontrar y visualmente jerarquizada.

El diseño debe transmitir profesionalismo y capacidad técnica sin parecer una página corporativa genérica.

# 4. Contenido y secciones

La web debe incluir como mínimo:

* Navbar
* Hero
* Sobre mí
* Habilidades / conocimientos
* Proyectos
* Información profesional
* Contacto
* Footer

## Navbar

Debe permitir navegar fácilmente por las diferentes secciones.

Debe ser sencilla y discreta, sin parecer una navbar típica de SaaS.

Incluir:

* Sobre mí
* Habilidades
* Proyectos
* Contacto

Y accesos externos a:

* GitHub
* LinkedIn
* CV

## Hero

Debe presentar rápidamente:

* nombre
* profesión / especialidad
* breve descripción
* enfoque como desarrollador

No quiero el típico hero de SaaS:

> "Build better products with the power of AI"

Quiero personalidad.

Debe existir una llamada a la acción clara para explorar los proyectos.

## Sobre mí

Una sección breve y visualmente interesante que permita conocer mejor al desarrollador.

Debe priorizar información profesional relevante y evitar bloques excesivamente largos de texto.

## Habilidades

Mostrar:

* lenguajes
* frameworks
* herramientas
* bases de datos
* cloud
* conocimientos técnicos

No quiero simplemente una cuadrícula de cards con logos.

Busca una presentación más original y coherente con la identidad visual general.

Organiza las tecnologías para que un recruiter pueda escanearlas rápidamente.

## Proyectos

Esta debe ser la sección más importante de toda la web.

Los proyectos deben tener mucho peso visual.

Cada proyecto debería poder mostrar:

* nombre
* descripción
* problema que resuelve
* tecnologías utilizadas
* imágenes/mockups
* enlaces
* GitHub cuando corresponda
* resultados o métricas ficticias cuando sea apropiado

Los proyectos no deben parecer simples cards genéricas.

Utiliza:

* diferentes tamaños
* diferentes composiciones
* diferentes proporciones
* imágenes grandes
* numeración
* etiquetas tecnológicas
* información contextual
* composiciones asimétricas

Los proyectos deben sentirse como casos reales de trabajo, no como una galería de tarjetas.

## Información profesional

Incluir:

* experiencia
* formación
* certificaciones
* tecnologías principales
* otros datos relevantes

La información debe ser concisa y fácil de escanear.

## Contacto

Debe existir una sección de contacto clara, visualmente integrada con el resto del portfolio.

Puede incluir datos ficticios de demostración.

## Footer

Debe incluir:

* nombre
* breve descripción
* GitHub
* LinkedIn
* email
* navegación básica

# 5. Dirección visual

Quiero una interfaz con una identidad visual propia y reconocible.

## Concepto principal

La estética debe ser:

**TECNOLÓGICA + EDITORIAL + CREATIVA + ROJA**

La sensación tecnológica debe ser evidente, pero no mediante clichés de cyberpunk, hacker o interfaces futuristas genéricas.

Debe sentirse inequívocamente como el portfolio de un ingeniero informático.

---

La sensación tecnológica debe surgir principalmente de:

* composición modular
* estructuras de información
* numeración de secciones y proyectos

* etiquetas de tecnologías
* indicadores visuales

Estos elementos deben utilizarse con intención y moderación.

La sensación tecnológica debe estar presente principalmente en:

* estructura
* tipografía
* información
* composición
* jerarquía visual
* microinteracciones

# 7. Lenguaje editorial

La parte editorial debe aparecer mediante:

* tipografía serif de personalidad
* titulares de gran escala
* composiciones asimétricas
* espacios negativos
* reglas y separadores
* numeración
* diferentes escalas tipográficas
* composiciones similares a una publicación tecnológica
* imágenes y mockups integrados en la composición

La combinación debe sentirse como:

**portfolio técnico de desarrollador + publicación editorial tecnológica contemporánea.**

# 8. Paleta de colores — ROJO COMO IDENTIDAD

La identidad cromática debe estar construida alrededor del rojo.

El rojo debe ser el color distintivo de la marca personal y reconocerse a lo largo de toda la página.

No debe limitarse a botones.

Debe utilizarse estratégicamente en:

* numeración
* reglas
* separadores
* indicadores
* pequeños textos técnicos
* enlaces importantes
* estados activos
* detalles de proyectos
* elementos tipográficos destacados
* pequeños elementos gráficos
* llamadas a la acción

El rojo debe funcionar como un hilo conductor visual.

## Distribución aproximada

* 70–80% tonos neutros
* 15–20% tonos secundarios/oscuros
* 5–10% rojo como color de identidad/acento

No quiero una página completamente roja.

## Rojo

No utilices automáticamente `red-500`.

Busca un rojo con personalidad.

Preferentemente:

* rojo carmesí profundo
* rojo bermellón
* rojo ladrillo sofisticado
* rojo sangre editorial

Puedes utilizar una combinación similar a:

* rojo principal: `#B4232C`
* rojo oscuro: `#7F1820`
* rojo claro: `#D94B52`

Ajusta estos valores si encuentras una combinación visual mejor.

## Neutros

Utiliza neutros con carácter:

* negro cálido
* carbón
* blanco roto
* crema
* gris cálido
* tonos de papel

Evita que parezca simplemente:

`white + slate-900 + red-500`.

# 17. Tecnología y estructura del proyecto

## IMPORTANTE

La entrega **NO debe ser un único `index.html`**.

Quiero una estructura moderna basada en:

* React
* TypeScript
* CSS

Debes entregar como mínimo:

```text
app.tsx
app.css
script.ts
```

Si necesitas otros archivos auxiliares, puedes crearlos únicamente cuando estén realmente justificados.

## Archivos principales

### `app.tsx`

Debe contener:

* estructura principal de la aplicación
* componentes React
* secciones
* datos que se muestran en la interfaz
* composición de proyectos
* navegación
* elementos interactivos

Organiza el código de forma limpia y modular.

No conviertas `app.tsx` en un bloque gigantesco y desordenado.

### `app.css`

Debe contener:

* identidad visual
* variables CSS
* colores
* tipografía
* layout
* responsive
* animaciones
* estados
* componentes visuales específicos

El rojo debe estar definido mediante variables CSS para que sea fácil modificar posteriormente.

Por ejemplo:

```css
:root {
  --color-red: ...;
  --color-red-dark: ...;
  --color-paper: ...;
  --color-ink: ...;
}
```

No dependas exclusivamente de clases genéricas de Tailwind para construir la identidad visual.

### `script.ts`

Utilízalo para la lógica/interactividad que realmente lo necesite.

Puede manejar:

* navegación móvil
* pequeñas interacciones
* estados
* scroll
* comportamiento de navegación
* microinteracciones
* pequeñas mejoras UX

Mantén el código sencillo.

No añadas lógica innecesaria.

# 25. Revisión final

Antes de terminar, revisa visualmente y conceptualmente el resultado.

Pregúntate:

> ¿Podría cambiar el nombre, logo y proyectos y vender esta misma interfaz como otra startup SaaS?

Si la respuesta es sí, el diseño es demasiado genérico.

También:

> Si elimino el texto que dice que soy ingeniero informático, ¿la interfaz sigue transmitiendo una sensación tecnológica?

> ¿El rojo funciona como identidad visual y no simplemente como color de acento?

> ¿La combinación tecnología + editorial es evidente?

> ¿La web evita la estética hacker/cyberpunk?

> ¿Parece diseñada específicamente para un desarrollador?

> ¿Un recruiter puede entender quién soy y qué sé hacer en menos de 30 segundos?

> ¿Los proyectos son realmente protagonistas?

> ¿La identidad roja, editorial y tecnológica se siente intencional?

> ¿La web mantiene personalidad en móvil?

> ¿Los datos ficticios están claramente estructurados para poder reemplazarlos?

> ¿El código está correctamente separado entre `app.tsx`, `app.css` y `script.ts`?

La web final debe sentirse como una identidad visual diseñada específicamente para un portfolio profesional de ingeniería informática.

Debe ser:

**profesional, tecnológica, editorial, creativa, roja, memorable y técnicamente creíble.**

No debe sentirse como una combinación de componentes populares de Tailwind, shadcn/ui o plantillas de SaaS.

Los datos utilizados en esta primera versión son **ficticios y únicamente sirven para demostrar visualmente cómo quedaría el portfolio**.
